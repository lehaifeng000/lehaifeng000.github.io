ssh通过跳板机连接目标机器

本文目录
  1. 1. 配置跳板机
  2. 2. 配置目标机器
  3. 知乎原文

平时在ssh直接连接服务器的时候，可以一行ssh命令连接，调试程序也可以通过vscode的remote插件，但是有时候无法直接连接服务器，而是要先登录到跳板机(一般是处于安全考虑设计的堡垒机)，再通过跳板机登录服务器的话，ssh需要多一行命令不说，vscode remote由于无法直接连接到服务器，导致没法在线调试程序。

通过查文档和找一些帖子找到了解决这个问题的方法，记录一下作为备忘。

SSH 设置连接的方法可以参考此前的远程部署笔记。

1. 配置跳板机

在 SSH 的 config 文件中添加一个到跳板机的连接，并按管理员要求使用 ssh-copy-id 配置密钥。下面是脱敏配置示例，代替原配置截图。

Host tb
    HostName jump.example.com
    User jump-user

2. 配置目标机器

在同一个文件中添加到目标服务器的连接，增加一行 ProxyCommand ssh -q -x -W %h:%p tb，其中 tb 是前面设置的跳板机别名。完整示例：

Host g1
    HostName compute.example.internal
    User compute-user
    ProxyCommand ssh -q -x -W %h:%p tb

设置完同样按授权方式配置公钥。现在可以直接在本地通过 ssh g1 连接目标服务器，VS Code Remote-SSH 也可以选同一个条目在线调试。
